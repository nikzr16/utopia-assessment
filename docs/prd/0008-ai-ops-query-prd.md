## Purpose

Managers can see the numbers on the KPI dashboard (0007), but a quick
question such as "What jobs did Ali complete last week?" still means picking
a period, a branch, and a technician by hand. This PRD adds an **Ask**
assistant inside the portal: a person types an operational question in plain
language and gets a short, clear answer with the records behind it, built
only from whitelisted, role-scoped database reads.

Source: the brief's AI Module — Operations Query Window (example questions:
"What jobs did technician Ali complete last week?", "Which technician
completed the most jobs this week?", "How many jobs were completed today?";
flow: question → system interprets → database retrieves → AI formats the
answer; focus: how AI integrates with system data, how queries retrieve
relevant records, clear answers, how limitations are handled; the README must
list the supported query types and the limitations;
`docs/prd/0000-programmer-assessment-brief.docx`).

## Goals

- A Manager types a question in everyday English or Malay and, within
  seconds, gets a one- or two-sentence answer plus a table of the records
  behind it, each order opening in their portal.
- The answer is trustworthy: every number and record comes from whitelisted
  read functions (the same `kpi_*` functions as the dashboard, so the two
  never disagree), and the table is drawn from the database rows, not typed
  by the AI.
- The AI never gets more access than the person asking: it can only choose
  from a fixed menu of lookups, and the server runs each one with the
  person's own permissions (Admins / Finance every branch, Managers the
  branches they cover, technicians only their own jobs).
- Limits are handled openly: out-of-scope questions, other branches,
  ambiguous names, empty results, and requests to change data each get a
  clear, honest reply instead of a guess.
- The person can see how each answer was found (lookups, inputs, exact
  dates).
- The README explains the supported question types, how the AI is used, and
  its limits, as the brief asks.

## Non-Goals

- Optional advanced AI challenges: workflow supervisor alerts, document
  understanding, overload insights (0009).
- Vercel deployment (0010); the Edge Function is deployed to the hosted
  Supabase project only.
- Changing any data from the assistant (no creating, assigning, approving,
  or closing orders by chat).
- Free-form SQL, reports, or charts generated by the AI.
- Voice input, file upload, or answers sent by email / WhatsApp.
- Training or fine-tuning a model on company data.
- App-side rate limits (Q14: OpenAI's own limits and spend cap only).

## User Stories

1. **As a Manager**, I want to ask "What jobs did Ali complete last week?" and see the jobs listed so that I do not have to search the dashboard.
2. **As a Manager**, I want to ask "Which technician completed the most jobs this week?" so that I know who is leading without opening the leaderboard.
3. **As a Manager**, I want to ask "How many jobs were completed today?" so that I can check the day's progress at a glance.
4. **As a Manager**, I want to ask a follow-up ("and last week?") and come back to an earlier chat so that I do not retype context.
5. **As a Manager**, I want to open any order in the answer so that I can check the details behind it.
6. **As a Manager**, I want the answer to say which dates and branches it covers so that I know exactly what "last week" meant.
7. **As a Manager**, I want a clear reply when I ask about a branch I do not cover, a name that matches two people, or something the assistant cannot answer, so that I am never misled.
8. **As an Admin**, I want to ask across all branches and see a log of every question asked so that I can answer company-wide questions and audit use.
9. **As Finance**, I want to ask about completed and collected amounts and unpaid jobs so that I can check money questions quickly.
10. **As a Technician**, I want to ask about my own jobs ("How many jobs did I finish this week?") so that I can check my work from my phone.
11. **As the business**, I want the AI to read only through whitelisted, role-scoped lookups, never change data, and never see customer phone numbers or addresses, so that a typed question can never leak or damage records.

## Constraints

- The AI chooses only from the fixed lookup menu with typed inputs; the
  server checks every input before calling the database. No AI output is ever
  run as SQL. At most 3 lookups per question.
- Lookups run as the person asking (their sign-in token), so row-level
  security and the `kpi_*` role checks apply; the Edge Function holds no
  database secret key for this feature.
- Read-only for business data. The only new writes are the person's saved
  chats and the Question log, both removed after 7 days.
- Data sent to OpenAI: the question, earlier turns of that chat, and the
  structured rows a lookup returns, without free-text notes or comments and
  without customer phone numbers or addresses (Q10, Q11).
- Every database change is a new timestamped migration; 0000–0007 migrations
  are committed and append-only. Hosted changes ship with SQL and deploy
  steps (`docs/draft/0008-supabase-update.sql`), plus the steps for the user
  to set the OpenAI key as a Supabase secret.
- Speed target: a typical answer in under 8 seconds, never more than
  20 seconds before an error message.
- The chat bubble must not cover important buttons on any page and must work
  at 375 px wide.
- Automated tests never call the real AI service: the AI step is replaced by
  a test double; the real service is checked in the manual check.
